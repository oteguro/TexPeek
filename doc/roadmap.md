# TexPeek ロードマップ

## 目的

macOS でゲーム用テクスチャの内部構造を確認できるビューアーアプリを作る。
最初の対象は DDS とし、Mip レベル、配列要素、3D スライス、キューブマップのフェイスを
選択して表示できることを中心機能とする。
Finder のサムネイルと Quick Look 拡張は、本体アプリの後で必要性を評価する。

## 標準機能について確認したこと

2026-11-03、この開発環境の Image I/O で `assets` の RGBA8 と BC1〜BC7 の
全 8 種類の DDS をデコードできた。Finder でも BC5 を含むサムネイル・プレビューの表示を確認した。
単純な 2D DDS を画像として表示する機能は、すでに標準機能で満たせる場合がある。
ただし、この結果はすべての macOS バージョンや DDS の内部形式への対応を保証するものではない。

## 基本方針

- 本体アプリは Swift を中心に実装する。
- 本体アプリを先に実装し、サブリソースの選択と表示を優先する。
- Finder のサムネイル拡張を追加する場合は `QLThumbnailProvider` を使用する。
- Quick Look の静止画像には `QLPreviewProvider`、操作 UI が必要ならビューコントローラー方式を検討する。
- DDS の解析・デコード・画像変換を共通モジュールにまとめ、将来の拡張からも利用できるようにする。
- BC 圧縮の展開には外部ライブラリを使用する。第一候補は [bcdec](https://github.com/iOrange/bcdec)。
- 初版は CPU でデコードして `CGImage` に変換する。Metal による高速化は必要性を確認してから検討する。
- DDS の既定アプリを TexPeek に変更することを、サムネイルやプレビュー利用の条件にしない。
- 本体アプリの常駐を必要としない。

## 想定構成

| 要素 | 役割 |
| --- | --- |
| TexPeek アプリ | ファイルを開き、Mip・配列要素・スライス・フェイスを選んで表示 |
| 共通デコードモジュール | DDS ヘッダー解析、サブリソース索引、BC 展開、表示用画像の生成 |
| Thumbnail 拡張（後続候補） | Finder が要求するサイズのサムネイルを生成 |
| Preview 拡張（後続候補） | Quick Look 向けのプレビューを生成 |
| bcdec | C のライブラリとして組み込み、BC ブロックを展開 |

bcdec は DDS コンテナ全体の読み込みを担当しない。
DDS ヘッダーの解析、データ範囲の検証、ブロックの配置、画像の端の処理は共通モジュールが担当する。

## 初版の対応範囲

- 2D テクスチャの表示から始め、初版の完了までに Mip・配列要素・3D スライス・キューブフェイスの選択に対応する。
- 従来の DDS ヘッダーと DX10 拡張ヘッダーを解析する。
- 非圧縮の RGBA/BGRA 8bit、BC1・BC2・BC3・BC4・BC5・BC7 を対象とする。
- 非圧縮形式は対応するビットマスク・DXGI 形式を明示し、未知の形式はエラーにする。
- BC4 はグレースケール、BC5 は R/G チャンネルを表示する方針とする。
- 法線マップの Z 成分復元など、用途を推測する変換は初版では行わない。
- 透明部分には市松模様を表示する。
- sRGB と linear、ストレートアルファと乗算済みアルファの扱いを整理し、表示時の変換を統一する。
- 選択中のサブリソースだけをデコードし、不要な全展開を避ける。
- 配列要素と 3D の深度スライスは別の選択項目とする。3D の深度は Mip ごとに変わる。
- キューブマップは `+X / -X / +Y / -Y / +Z / -Z` のフェイス選択に対応する。
- キューブマップ配列はキューブの配列インデックスとフェイスを別々に選べるようにする。
- 未対応のリソース構成は明示し、通常の 2D と誤認しない。

## 実装ステップ

### 1. プロジェクト基盤

- [ ] 対象 macOS バージョン、対応 CPU、Xcode の要件を決める。
- [ ] 本体アプリと共通モジュールのターゲットを作る。
- [ ] 共通モジュールと C ライブラリの接続方法を決める。
- [ ] bcdec のライセンスを確認し、使用するリビジョンを固定してライセンス表記を同梱する。
- [ ] DDS の既存 UTI と競合の有無を調べ、必要な imported type 宣言を追加する。
- [ ] 本体は `Viewer` / `LSHandlerRank = Alternate` を基本とし、既定アプリを変更する処理は追加しない。

`Alternate` は開くアプリの候補として登録する設定であり、既定アプリにならないことを保証するものではない。
他の対応アプリがない環境も含め、Launch Services の動作を確認する。

### 2. DDS デコーダー

- [ ] ヘッダー、形式、寸法、ミップ数を取得する。
- [ ] リソース種別、配列数、深度、フェイスの有無を取得する。
- [ ] Mip・配列要素・フェイス・深度スライスから、寸法とデータ範囲を参照できる索引を作る。
- [ ] データ長・オフセット・サイズ計算を検証し、整数オーバーフローを防ぐ。
- [ ] 初版対象の非圧縮形式を表示用ピクセルへ変換する。
- [ ] bcdec で対象 BC 形式を展開する。
- [ ] 4 の倍数でない寸法や、4×4 未満の画像を正しく処理する。
- [ ] 色空間とアルファの処理を含めて `CGImage` を生成する。
- [ ] 要求サイズに応じたミップ選択と、処理量・メモリ使用量の上限を設ける。
- [ ] 未対応形式・破損ファイルを識別できるエラーを返す。

### 3. テクスチャを確認するビューアーアプリ

- [ ] 「開く」とドラッグ＆ドロップで DDS を読み込む。
- [ ] ウィンドウに合わせた表示、拡大縮小、原寸表示を提供する。
- [ ] 透明部分の市松模様を表示する。
- [ ] 画像サイズ・圧縮形式・ミップ数を表示する。
- [ ] Mip レベルを選択でき、選択したレベルの寸法を表示する。
- [ ] 配列要素と 3D スライスを、該当するリソースで選択できる。
- [ ] キューブマップのフェイスと、キューブ配列の要素を選択できる。
- [ ] Mip 切り替えでスライス数が減る場合、選択値を有効範囲に収める。
- [ ] 該当しない選択項目は無効化または非表示にする。
- [ ] 未対応形式や読み込み失敗の理由を表示する。

### 4. 本体アプリの検証と配布

- [x] RGBA8 と BC1〜BC7 の 256 × 256 サンプルと比較 PNG を用意する。
- [ ] Mip ごとに識別可能な画像、配列、3D、キューブマップ、キューブ配列のサンプルを用意する。
- [ ] 各サンプルの出典・ライセンスまたは生成方法を記録する。
- [ ] 基準画像と比較し、色・アルファ・チャンネル・向きを確認する。
- [ ] 各 Mip・要素・スライス・フェイスのデータ範囲と表示が正しいことを検証する。
- [ ] DX10 ヘッダー、端数寸法、破損データ、巨大な寸法値を検証する。
- [ ] 対応対象の macOS / CPU でビルドと実機表示を確認する。
- [ ] サンドボックス内のファイルアクセスを確認する。
- [ ] 配布経路を決め、必要な署名・公証とインストール手順を整える。

### 5. Finder サムネイル（本体アプリの後で評価）

- [ ] 標準サムネイルで不足する具体例を確認し、拡張を追加するか判断する。
- [ ] 追加する場合、拡張ターゲットと `QLSupportedContentTypes` を設定する。
- [ ] `QLThumbnailProvider` から共通モジュールを呼び出す。
- [ ] 要求サイズと表示スケールに合わせ、縦横比を保持した画像を返す。
- [ ] 大きな画像や多数のファイルでの生成時間・メモリ使用量を確認する。
- [ ] DDS の既定アプリが別のアプリでもサムネイルが表示されることを確認する。

### 6. Quick Look プレビュー（本体アプリの後で評価）

- [ ] 標準プレビューで不足する具体例を確認し、静止画像か操作 UI 付きかを決める。
- [ ] 追加する場合、拡張ターゲットと `QLSupportedContentTypes` を設定する。
- [ ] 静止画像方式では `QLPreviewProvider` と `QLPreviewReply` を利用する。
- [ ] 操作 UI 方式では `NSViewController` と `QLPreviewingController` を利用する。
- [ ] Finder でスペースキーを押して表示・切り替え・終了できることを確認する。
- [ ] 本体アプリが終了した状態でも、両拡張が動作することを確認する。

- [ ] 拡張の登録・有効化と配布時の署名を確認する。
- [ ] 他の DDS 対応アプリや Quick Look 拡張との共存を確認する。

## 初版後の候補

- BC6H と浮動小数点 HDR 画像の表示、トーンマッピング・露出調整。
- キューブマップの全フェイスの展開表示、環境マップの立体表示。
- RGBA チャンネル切り替え、法線マップ表示。
- KTX / KTX2 など、DDS 以外のゲーム用テクスチャ形式。
- 計測に基づく並列化や Metal による高速化。

Quick Look 内に操作 UI が必要になった場合は、
`NSViewController` と `QLPreviewingController` によるプレビューへの移行を検討する。
共通デコーダーはそのまま利用できる構成にする。
